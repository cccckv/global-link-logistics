# 全局交互规则与业务知识库 (Project & Agent Rules)

## 1. 严格遵守讨论与提问模式 (Discussion & Q&A Mode)
- **禁止提前直接修改代码**：当用户提出“讨论”、“我们目前是在讨论”、“探讨一下”、“分析一下”或纯提问疑点时，**绝对不得主动修改任何源代码或执行写操作**。
- **职责范围**：在讨论/提问模式下，只能深入分析业务逻辑、梳理技术架构、比对数据字段并给出明确的对比方案与优缺点；
- **执行触发条件**：只有在用户明确确认并下达执行指令（例如“按照方案1执行”、“确认修改”、“提交修改”）后，方可对代码进行实际修改。

## 2. 物流计费与双轨生命周期核心经验
- **散货拼箱 (SEA_LCL)**：按最新实测方数计费（元/方），总应收 = $\sum (\text{实测方数 } \text{m}^3 \times \text{应收体积单价}) + \sum \text{应收杂费}$；
- **空运专线 (AIR)**：按最新实测/计费重量计费（元/kg），总应收 = $\sum (\text{实测重量 } \text{kg} \times \text{应收重量单价}) + \sum \text{应收杂费}$；
- **两段式生命周期**：阶段 1 记录预估数据作为参考价（看板展示 `[预估参考 (待实测)]`）；阶段 2 仓库实测录入后，系统**全自动重新核算并直接覆盖持久化**数据库运单主表的 `receivableAmount`（总应收）、`payableAmount`（总成本）与 `profitAmount`（利润），看板切换为 `[实测核量结算]`；
- **包干一口价**：锁定协议总应收，成本随实测尺寸与干线支出动态核算，单票利润实时联动；
- **附加杂费**：全生命周期任意节点增删杂费均实时触发主表财务总账动态刷新。

## 3. 工程与数据规范
- **Prisma 分页参数整型化**：URL Query 中的 `limit`/`page` 必须经 `Number()` 转换为整数后再传给 Prisma `take`/`skip`，防止运行时类型崩溃；
- **前端除零安全保护**：计算体积/重量偏差比时必须做除零防范（`estVol > 0.00001`），杜绝渲染 `(undefined%)`；
- **货柜全部完结校验**：货柜流转至 `COMPLETED`（全部完结）时，强制校验名下所有拼箱运单是否都已达到 `DELIVERED`（已签收），未完结时严禁标记完结；
- **Git 分支准则**：所有代码变更与重构严格保留在 `refactor` 分支。
