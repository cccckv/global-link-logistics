# 13. 空箱还柜业务流转 (Empty Container Return)

## 1. 业务背景
在海运整柜（FCL）业务中，集装箱运抵客户目的地并完成拆箱卸货后，产生空箱。此时需要将空箱归还至船司指定的码头或堆场（Offdock CY）。此过程涉及状态跟踪以及可能产生的滞箱费（Detention Fee）、修箱费（Damage Fee）等额外费用的核销。

## 2. 状态机 (Return Status)
针对单个集装箱的还柜进度，设计独立于主生命周期状态（`ContainerStatus`）的还柜状态机（`ContainerReturnStatus`），实现状态解耦。

| 状态枚举值 (Enum) | 中文说明 | 业务触发场景 | 限制 / 前置条件 |
| :--- | :--- | :--- | :--- |
| `UNFINISHED` | **未完结** | 货柜尚在海运、清关或派送途中，未完成收货人签收与卸货。 | 这是默认状态，此时不具备还柜条件。 |
| `PENDING` | **待还柜** | 客户已完成拆箱卸货，货柜已空，正在等待指派车队去还柜。 | 主业务流程达到 `COMPLETED` 或送达签收后流转至此。 |
| `RETURNING` | **还柜中** | 已向堆场/码头进行预申报 (Pre-advise) 并已派司机前往还柜的路上或排队中。 | |
| `COMPLETED` | **已还柜** | 码头/堆场已正式接收空箱。 | 货柜物理流转生命周期正式终结。 |

## 3. 额外费用追踪 (Extra Charges)
在还柜过程中，可能会因为超期归还、箱体损坏或洗箱等原因产生额外费用。采用字段标记方式记录，而非阻塞式状态，以适应灵活的实际操作：

* **费用入账机制**: 产生的异常费用（金额和币种）将直接调用 API 写入系统的统一费用表 `ContainerFee` (例如记录为 `THC_OVERSTAY_FEE` 或其他杂费类目)，以便能够自然地归入该货柜的整体物流成本核算中，在“集装箱整柜跟踪”等成本管理界面可见。
* **快捷异常标识 (`hasExtraCharge` 与 `extraChargeReason`)**: 在货柜主表 `ContainerMaster` 中，仅保留 `hasExtraCharge` (布尔值) 和 `extraChargeReason` (备注/事由) 作为扁平标识，用于在还柜列表界面上实现一键红灯高亮和快速筛选，避免为判断异常而每次查询关联费用表。
* **付款凭证 (`extraChargeProofUrl`)**: （暂缓实现）针对需要财务介入或垫付的费用，预留了支持上传付款水单（Deposit Slip/Receipt）的字段。

## 4. 与主表的关联
空箱还柜相关字段直接挂载于整柜业务主表 `ContainerMaster` 中，无需额外分表。这样可以确保在列表查询和单据导出时，前端能够最扁平地获取所有信息。
